# 软选择器（selector）：按语义找，找不到才退回坐标

> 结论先行：**硬坐标在窗口尺寸/主题/版本变化后必崩（实测偏 47 px）；
> 软选择器能活。** 但软选择器依赖 OCR/模板质量，所以必须有降级链。

## 一、三级降级

```python
from computer_mcp import selector
r = selector.resolve(rect, {"text": "发现", "within": [0, 0, 0.6, 1.0],
                            "template": "wx_discover.png",
                            "rel": [0.0351, 0.359]})
# → {"ok": True, "at": (662, 655), "method": "text"|"template"|"rel", "detail": ...}
```

| 级别 | 用什么 | 适用 | 实测 |
|---|---|---|---|
| ① text | 窗口内 OCR，找包含 query 的那一行 | 有文字的控件（会话名、菜单项、按钮字） | 命中「发 现」score 1.0 |
| ② template | `cv2.matchTemplate` | 纯图标按钮（微信左栏、工具栏） | score 1.00 命中 |
| ③ rel | 窗口比例坐标 | 最后兜底 | 一定返回 |

**`method` 必须如实上报**：统计里 `rel` 占比高 = 这套选择器在该应用上没起作用。

## 二、动作里怎么用

```json
{"kind": "click",
 "find": {"text": "文件传输助手", "within": [0.06, 0.1, 0.24, 0.9],
          "rel": [0.142, 0.331]}}
```
`find` 命中就点它；全失败才用 `rel_frac`（点击详情里会打印 `[text]` / `[template]` / `[rel]`）。

## 三、两个必踩的坑（都实测过）

| 坑 | 现象 | 修法 |
|---|---|---|
| OCR 行是**扁平** `{text,x,y,w,h}` | 按 `rect` 取坐标 → 静默取不到，选择器永远失败 | `_geom()` 兼容扁平 / 嵌套 rect / 四元组 |
| `cv2.imread` 读**中文路径**返回 None | 模板永远匹配不上 | `cv2.imdecode(np.fromfile(path, np.uint8), IMREAD_GRAYSCALE)` |

## 四、可复现验证

```powershell
python tools\selector_demo.py
```
自己开一个 Tk 窗口当靶子 → 量一次 → 挪走+改尺寸 → 三种各点一次。

```

```

## 五、边界

```
· 图标类控件没有文字 → 只能靠模板；模板要在**本机当前主题**下重新截
· OCR 对 12px 以下小字、灰字、深色底上的深色字经常读不出（可放大 3× 再 OCR）
· within 区域给错会排除目标（所以默认不传 = 整窗）
· 文本选择器选中"看起来对"的行仍需后置条件（expect）确认动作生效
```

## 六、真实界面上的三个硬要求（2026-10-27 实测微信）

同一条 `resolve` 调用，参数不同结果完全不同：

| 目标 | 参数 | 结果 |
|---|---|---|
| 会话行「文件传...」 | `within=[0.05,0.08,0.23,0.84]` **+ `upscale: 2`** | ✅ text，score 0.85，165 ms |
| 聊天标题「文件传输助手」 | `within=[0.02,0,0.55,0.09]` | ✅ text（OCR 读成「文亻牛传输助手」，LCS 救回）21 ms |
| 输入框 | `text:"发送"` | ❌ 退回 rel（发送键是灰的/太小）→ **这类无文字区域就该用 rel** |

### ① `upscale` 不是可选项

11px 的列表行名字，**1× OCR 完全读不到**（只读到时间戳和角标）。
实测：1× → 17 行无此名；**2× → 22 行，命中**；3× → 28 行也命中但更慢。
**小字一律 `upscale: 2`**（3 只在小字极小/极灰时用）。

### ② `boost=True` 会毁掉中文

```
1×：文件传        boost：亻牛亻专      ← 「件」被拆成「亻牛」
```
**CJK 上永远不要开 boost**（它适合英文小字）。

### ③ 截断要按「最长公共前缀 ≥3」判

OCR 把「文件传...」读成 **「文 件 传 ． “ 03 ： 52」**（名字后面粘了时间）。
所以不能要求"整串都是 query 的前缀"，而是：
```python
n = 最长公共前缀长度(q, t);  n >= 3 → 0.85 分
```

### 实测占比（这就是"要不要放大"的判据）

```
3 个目标：2 个 text + 1 个 rel（输入框无稳定文字）→ rel 占比 33%
结论：可以放大，但**"无文字区域"保留 rel 是有意为之**，不算退化
```
