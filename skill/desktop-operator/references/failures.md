# 失败模式目录（我自己犯过的，逐条对应修法）

> 这份是**我的病历**，不是通用建议。
> 用法：卡住的时候先在这张表里找症状，找到就照"正确做法"做，别重新发明。

## A. 看 / 判断类

| # | 症状 | 真因 | 正确做法 |
|---|---|---|---|
| A1 | 点了"没反应"，反复换工具试 | **没有先看窗口列表**：会话可能开在**另一个窗口**里（微信独立聊天窗，标题=聊天名） | `EnumWindows` 列一遍（标题/尺寸/位置），按标题找目标窗口 |
| A2 | 明明有截图，却去 OCR 找按钮 | 忘了截图就是地图 | **图上量坐标**，OCR 只确认文字 |
| A3 | 点击"全部偏移 1.5 倍" | 没声明 DPI 感知 | 第一行 `SetProcessDpiAwareness(2)` |
| A4 | 判据"没变化"就报失败 | 用**瞬时**变化率判断，画面变完就稳 → 竞态 | 改**锁存**：记下"自某时刻起出现过的最大变化率" |
| A5 | 滚动两下，第二下报失败 | 列表到底了**本来就不变** | 滚动类步骤的判据用 `stable`（滚完稳定），不要 `changed` |
| A6 | 文字断言永远不成立 | OCR 把 `TRACK-OK-2152` 读成 `TRACKOK2152` | 归一化（去非字母数字、转小写）+ LCS ≥0.8 |
| A7 | 文字断言区域写小 → 目标在区域外 | 默认给了 `[0.05,0.05,0.9,0.6]` 之类的"合理"值 | **不传 region = 整窗**；要缩小就先用拼图确认目标在里面 |
| A8 | 语音/输入法把中文吃掉 | IME 抢键 | 剪贴板粘贴；或 `ImmAssociateContext(hwnd,0)` |

## B. 时间 / 卡死类

| # | 症状 | 真因 | 正确做法 |
|---|---|---|---|
| B1 | 一条命令卡 1 分钟以上 | 启动的子进程**继承了输出管道**（`cmd /c start`） | 用 `ShellExecuteW`；或 `stdout=DEVNULL, close_fds=True` |
| B2 | 开个应用要 1 分钟，我还不知道在等什么 | 没有**单步预算**：正常 5–8 秒的动作不该等 60 秒 | 每步带 `budget_ms`，超 3 倍就截图并停车（看门狗） |
| B3 | 长脚本跑到底失败，不知道哪一步断的 | 一次调用做太多步，中间没有确认点 | 一步一截图；或用 track 的 step 边界 |
| B4 | 等 sleep 等到天荒地老 | 用固定 sleep 当同步 | 用判据（`stable` / `changed` / `text`）+ 超时 |

## C. 状态 / 输入类

| # | 症状 | 真因 | 正确做法 |
|---|---|---|---|
| C1 | 画面正常但点击/按键全无效 | `SW_HIDE` 后再显示，输入上下文坏了 | 永远 `SW_MINIMIZE`，不要 `SW_HIDE`；坏了只能真实点击或重启进程 |
| C2 | 窗口"能改尺寸但画面不动" | 鬼影窗口 | `SetWindowPos(SWP_FRAMECHANGED)`；判据：改尺寸后差异 >0.5 |
| C3 | 操作跑着跑着开始作用在**别的窗口**上 | 目标窗口失焦/被盖住 | 每步动手前：`HWND_TOPMOST` + 前台校验 |
| C4 | 打字打不进去 | 有模态对话框在吞键 | 先截图；track 已内置对话框特征词检测（`dialog_hits`） |
| C5 | 同一个按钮点两次反而取消 | 开关语义 | 只点一次，用外部证据验证（ACF/气泡/标题） |
| C6 | 窗口跑到屏幕外，点不到输入框 | 位置未归位 | 操作前挪到 (20,20) 并 `SWP_SHOWWINDOW` |

## D. 工程 / 流程类

| # | 症状 | 真因 | 正确做法 |
|---|---|---|---|
| D1 | 同一个按钮每次都要重新找 | **量到就写进配方**，没写 | 任务结束前更新 `recipes/<app>.json` 的 `measured_coords` |
| D2 | 改了代码但行为没变 | 字符串替换没断言，静默失败 | 每次 `assert old in s`；语法用 `compile()` 校验 |
| D3 | 单元测试全绿但功能崩 | 测试不启动真线程/真窗口 | 加"一次性自测"脚本（`tools/track_oneshot.py`），真跑 |
| D4 | 测试报 FAIL 但规则已经搬走 | 不变量测试还盯着老位置 | 规则搬家时同步改测试，并断言 `AGENTS.md` 仍指向 skill（断链也算失败） |
| D5 | 验证助手说 PASS 其实没测 | 全跳过 → 假绿 | 已修：全跳过判 UNKNOWN |
| D6 | 我写了个"万能脚本"，一跑就崩在某行 | 没在真实目标上分步验证 | 先一步一跑通则，再合并成脚本 |
| D7 | 语音指令理解偏了（"打开我的steamma"） | 直接按字面猜 | 先查已装应用/窗口标题/配方，确认目标再动手 |

## E. 收尾类

| # | 症状 | 真因 | 正确做法 |
|---|---|---|---|
| E1 | 桌面被我的窗口占满 | 忘记关 | 收尾：`close_windows` 关自己开的；**不要 SW_HIDE** |
| E2 | `%TEMP%` 堆满 `t_*.py` / 截图 | 没清理 | `clean.py --apply --keep 1`；`_draw` 上限 80 张 |
| E3 | 把用户的窗口关了 | 没区分"我开的"和"他开的" | 只关本次任务打开/使用的；有未保存改动先问 |

---

## 一句话总结（贴在脑门上）

```
卡住时的正确顺序：
  ① 截图看现在是什么状态（有没有对话框、窗口在不在、是不是另一个窗口）
  ② 列窗口列表（标题/尺寸/位置），别猜
  ③ 判活三连（前台/落点/重绘）
  ④ 才怀疑输入链路
  ⑤ 最后才怀疑系统/安全软件
```

**反例（我犯过的）**：先怀疑"SendInput 被拦" → 卸载安全软件 → 折腾两小时 → 真因是记事本的保存对话框。
