# 微信 4.x（Weixin.exe）— 已验证流程

> 实测环境：Windows 11 / 2560×1440 @150% / 微信窗口 442×581 面板 → 1566×1057 主窗口
> **UIA 完全不可见**（自绘渲染面），只能截图 + 坐标。

## 一、从「没开」到「能用」

```
① 启动：cmd /c start "" "C:\Program Files\Tencent\Weixin\Weixin.exe"
② 等 5–8 秒 → 会出现一个 **442×581 的小面板**（标题「微信」）
   上面三个入口：进入微信 / 切换账号 / 仅传输文件
③ **必须点「进入微信」**（记住：面板内相对位置 ≈ (0.500·W, 0.831·H)）
   —— 屏幕坐标 = 面板原点 + 上面的比例
   —— 键盘 Enter 也能激活它（面板默认按钮）
④ 点完会显示「正在进入」+ 转圈，等 4–6 秒 → 主窗口出现（1566×1057）
```

**忘记点「进入微信」= 后面每一步都对着静止的登录页操作**，这是最容易犯的错。

### 面板被挡住怎么办

新启动的窗口常常**在别的窗口后面**。先把它拉到前面再点：
```
点任务栏微信按钮（UIA 可找到，name≈「微信 - N 个运行窗口 已固定」）
或者 appkit.activate(hwnd)
```
判断：截图里能看到面板 → 才能点。看不到 → 先激活。

## 二、主窗口布局（1566×1057 基准，用比例算）

```
左栏图标列 x ≈ 0.037·W
   头像       y ≈ 0.066·H
   聊天       y ≈ 0.147·H   ← 回到聊天列表
   通讯录     y ≈ 0.224·H
   收藏       y ≈ 0.293·H
   发现       y ≈ 0.363·H   ← 朋友圈/视频号/搜一搜/游戏/小程序
   底部功能   y ≈ 0.72·H / 0.77·H

会话列表（第二列）x 0.06~0.28·W
   第 n 行 y ≈ 0.24 + (n-1)·0.083  （第 3 行「文件传输助手」≈ 0.343·H）

聊天区输入框 x ≈ 0.55·W, y ≈ 0.88·H
```

## 三、发一条消息（最短路径）

```
① 左栏点「聊天」          (0.037, 0.147)
② 点会话行（如文件传输助手，通常是第 3 行）  (0.142, 0.343)
   验证：右侧聊天区出现气泡/输入框（画面差异会很大，≥ 5）
③ 点输入框                (0.55, 0.88)   ← 必须点，否则焦点不在输入框
④ 剪贴板写 Unicode 文本 → Ctrl+V
⑤ Enter
⑥ 再点一次输入框，把光标挪走，然后截图确认气泡出现
```

**验证只认「气泡出现」**：截图里能看到绿色/灰色气泡 + 列表预览文字变了。

## 四、朋友圈

```
左栏「发现」(0.037, 0.363) → flyout 里点「朋友圈」(0.131, 0.149)
→ 朋友圈在同一个窗口内右半边打开（不是新窗口）
→ 滚动：鼠标移到内容区中心，mouse_event(WHEEL, -360) × N
```

## 五、血泪清单

| 坑 | 后果 | 记法 |
|---|---|---|
| **不点「进入微信」** | 一直在登录页，所有动作无效 | 看到小面板先点它 |
| **SW_HIDE 主窗口** | 再 SW_SHOW 后**画面正常但输入全死**（最小化→还原也救不回） | 清桌面用 `SW_MINIMIZE`，永不 `SW_HIDE` |
| 重跑 exe 想"唤单实例" | 会真的开出**第二个实例**，抢前台 | 别重跑；用任务栏按钮 |
| 点两次同一个 tab | 微信有些 tab 是切换语义，第二次把它关掉 | 只点一次，看结果再决定 |
| 窗口在「发现」页时直接点会话行 | 点的是 flyout 里的条目 | 先左栏切回聊天 |
| IME 抢键 | 中文打不进去 | `ImmAssociateContext(hwnd,0)` 或走剪贴板 |

## 六、★ 会话开在「独立窗口」里（2026-10-27 血的教训）

点会话列表里的一行，微信会**另开一个窗口**，标题就是聊天名（例：`文件传输助手`，919×971）。
主窗口右侧那块空白**不会**出现聊天内容 —— 看起来像"点了没反应"。

```
错误做法：点完会话行，盯着主窗口右侧看，以为失败 → 反复点 → 反复"没反应"
正确做法：点完立刻 EnumWindows，按**聊天名**找窗口：
          hwnd=7930160 '文件传输助手' 919x971 @(820,240)
          对它 SetWindowPos(HWND_TOPMOST) + 前台，再点输入框 (0.5W, 0.90H)
```

判据：主窗口右边缘可能露出**一条绿色气泡边**，那就是独立窗口被压住露出的角。

### 完整可用流程（实测发出《静夜思》03:34）

```
① 主窗口：左栏「发现」→「朋友圈」→ 滚轮下滑 N 次
② 主窗口：左栏「聊天」回会话列表
③ 点会话行 → 立刻找 **同名独立窗口**
④ 独立窗口：置顶 + 前台 → 点输入框 (0.5W, 0.90H) → 剪贴板粘贴 → 回车
⑤ 截图确认气泡（绿色，右侧）
```

## 七、软选择器在微信上的实测（2026-10-27）

同一套 `selector.resolve` 用在微信：「文件传输助手」和输入框**两次都退回 rel**。
原因（已修）：

| 现象 | 真因 | 修法 |
|---|---|---|
| 会话行文字是「文件传...」 | 界面**截断**了长名字，OCR 只读到「文件传」 | `score_line` 支持**前缀截断**匹配（0.85 分） |
| 输入框占位符「按住鼠标 语音输入文字」读不出 | 灰字、对比度低 | OCR 传 `upscale=3`（ocr_read 支持） |

**结论**：先别指望软选择器在自绘 UI 上一次到位；
`method=rel` 的占比才是判据 —— 占比高说明"选择器没起作用"，要继续补前缀/放大/模板。
