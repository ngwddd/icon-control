# desktop-operator · 桌面操作手

> **一句话**：桌面任务不是「调工具」，是「看着屏幕，一步一步动鼠标」。
> 工具只负责三件事：**看**（截图）、**动**（点/打/滚）、**记住流程**（宏/配方）。

## 0. 开工顺序（不许跳步）

```
① recipes/ 里有这个 app 的文件 → 照抄里面的坐标/流程/坑
② macros/ 里有对口宏        → macro_run 一次跑完
③ 都没有                    → 才自己一步步来（第 1 节）
```

配方和宏的位置（随 icon-control 包发布）：
`~/.dsh/tools/desktop-mcp/recipes/*.json` 与 `macros/*.json`

**为什么**：配方是拿时间换来的事实（按钮在哪、点几次、怎么验证）。重新发现一次 = 半小时。

## 1. 核心循环（唯一正确的节奏）

```
看一眼  →  决定一个动作  →  做  →  再看一眼
（截图）    （只做一个）              （截图对比）
```

### 三条铁律

1. **一步一截图**。每做一个动作就截一张，看过再走下一步。
   长脚本一口气跑到底 = 中间错了你不知道，最后失败了还得重来。
2. **坐标从图上量**，不要 OCR 找按钮。
   手里已经有截图，按钮就在图上第 N 个像素；OCR 只用来**确认文字**，不用来**定位按钮**。
3. **先确认窗口在最前面**。被别的窗口挡住时，点击落在遮盖窗口上，而你以为是"点了没反应"。

### 每步的成本（这就是为什么一步一截图更快）

| 做法 | 执行 | 我要读的输出 | 决策歧义 |
|---|---|---|---|
| 一步一截图 + 坐标 | 40–150 ms | 一行 `ok` + 一张小图 | **没有** |
| 一次长脚本 | 一样 | 一大段日志 | 有（哪步错了？） |

**真正的瓶颈是我读图的速度（一帧 640×360 ≈ 6–10 秒）**，不是抓屏（29 fps）。
所以：每步只给我**一张**图，别一次给五张。

## 2. 判活三连（宣布"没反应"之前必须过）

```
① 前台是不是它？   GetForegroundWindow() == hwnd
② 落点是不是它？   WindowFromPoint(x,y) → GetAncestor(GA_ROOT) == hwnd
③ 它会不会重绘？   移动/改尺寸后截图差异 > 0.5
```

三条全过还点不动 → 才考虑"输入被拦"。**缺 ③ 这条，你会在鬼影窗口上白折腾半小时。**

## 3. 已知假阴性清单（先排这些，别急着怪系统）

| 现象 | 真因 | 处置 |
|---|---|---|
| 打字没进去 | 有模态框（记事本"要创建新文件吗"、未保存提示）吞按键 | 先截图看有没有对话框 |
| 点了没反应 | 目标不在前台 / 被遮挡 / 落点是别的窗口 | 判活三连 |
| 点击全偏移 1.5 倍 | 进程没声明 DPI 感知 | 第一行 `SetProcessDpiAwareness(2)` |
| 窗口能改尺寸但画面不动 | ShowWindow 出来的**鬼影** | `SetWindowPos(..., SWP_FRAMECHANGED)` |
| 同一个按钮点两下反而取消 | 开关是**切换**语义（Steam 订阅、微信某些 tab） | **每张只点一次**，然后用外部证据验证 |
| 输入法吃中文 | IME 抢键 | `ImmAssociateContext(hwnd, 0)` 或走剪贴板粘贴 |

## 4. 输入的正确方式（按可靠性排序）

```
1. 剪贴板 + Ctrl+V      长文本/中文，绕开输入法和逐字敲（首选）
2. 逐字符 press/release（间隔 15 ms）  短文本；kb.type() 一次性灌会丢字（Win11 UWP 尤其）
3. 回车提交             比点"发送"按钮可靠（按钮可能点不中）
```

**永远不要**：逐字敲长文本、点 OCR 读到的"发送"两字、连点同一个开关。

## 5. 收尾（每次任务结束都做：**关窗** + 清理 + 还原）

```
① 关窗：用 close_windows（只发 WM_CLOSE，不杀进程）关掉**我打开或使用的**窗口；
   确实要退出整个应用才用 appkit.exit_app / exit_app（会清托盘残留进程）
   ⚠️ 不要 SW_HIDE 微信主窗口（会毁掉输入上下文）；清桌面用 SW_MINIMIZE
② 把任务开始前的那个窗口还原到前台
③ clean.py --apply 清临时文件
④ 报告里写清：关了哪些窗口、清了多大
```

**边界**：只关本次任务打开或用过的窗口；用户自己开的窗口不动；
有未保存改动的窗口（标题带 `*` 或弹保存提示）先问用户，不要替他选。

## 6. 工具分层（78 个工具里只有这几个是入口）

| 用途 | 工具 |
|---|---|
| 看 | `screenshot` / `screen_state`（只要"变没变"时用它，便宜） |
| 动 | `batch`（多步一次发）/ 坐标点击 / `type` |
| 整段 | `macro_run`（含断言与重试） |
| 认字 | `ocr_read` / `find_text`（只做确认，不做定位） |
| 记位置 | `layout_mem`（标定一次，归一化复用） |
| 高频闭环 | `sense` / `probe` / `run_script`（游戏类） |

其余（`screen_model` 实验性、`perceive`/`navigator` 内部件、30 个低层动作）**不要当第一步**。

## 7. 具体应用

- 微信 4.x（含「进入微信」面板、朋友圈、发消息）→ `references/wechat.md`
- Steam 创意工坊订阅 → `references/steam.md`
- UWP / CEF / Electron 通用（记事本、浏览器、自绘 UI）→ `references/uwp-cef.md`
- 坐标与缩放的细则（DPI、rel_frac、锚点记忆）→ `references/coords.md`

## 8. 什么时候**别**用这个 skill

```
· 能用 PowerShell / python / 文件操作做到的 —— 一律不要动鼠标
· 需要密码、支付、授权确认的 —— 交回用户
· 改系统服务/驱动/安全软件 —— 不做
· 用户正在打字或看视频 —— 不抢焦点
```
