# 发展历程（2026-10-25，一天之内）

> 这份文档按真实顺序记录每一次进步和每一次翻车。写它的目的不是好看，
> 而是让下一个人（或者下一个我）不必重踩一遍。

## 00:00-01:00 · 起点：一句"这个 MCP 效率很慢"

第一反应是怀疑 MCP 协议本身。实测单次调用 1.8 ms —— **猜错了**。
真因：默认给每个动作都附一张全分辨率 PNG 截图。

| 场景 | 耗时 | 响应体积 |
|---|---|---|
| 不带截图 | 1.8 ms | ~1 KB |
| 带截图（原始） | 128 ms | 962 KB |
| 带截图（0.5x JPEG q75） | **61 ms** | **121 KB** |

**改动**：重写 `computer_mcp/core/screenshot.py`；新增 `screen_state`（43 ms，无图）、
`wait_for_change`（事件驱动）、`capture_config`（运行时可调）。

**收获**：优化前先量。想当然的"协议慢"是错的。

## 01:00-02:00 · 第二次说"还是慢"：慢在往返

一个 20 步操作要 20 次模型调用。于是：

- `batch`：20 步合成 1 次调用，协议层 **2 ms**；
- UI 自动化五件套：`ui_tree` / `ui_find` / `ui_click` / `ui_invoke` / `ui_set_text`。

**踩坑**：某即时通讯软件 4.x（***） 的 `ui_tree` 只回 2 个节点（自绘渲染面）。Electron / CEF / 游戏同理。
**结论：UIA 只对原生控件有效，不是万能钥匙。**

## 02:00-03:00 · 宏 + OCR：给"看不见控件"的界面补眼睛

**宏**（一次调用回放整段，4 步 651 ms）：
- 坐标写相对窗口的 `rel`，窗口移动/缩放都不失效；
- 步骤可带 `expect`：做完验证"画面真的变了"，没变就中止；
- 两道防盗：目标最小化先 restore（否则 `GetWindowRect` 返回 -32000，点出去在屏幕外）；
  相对坐标越界拒绝执行。

**OCR**（Windows 内置引擎，无需 Tesseract）：
- 有 hwnd 时走 PrintWindow → **被遮挡也能读**；
- 中文按"去空格 + 最长公共子串"匹配：`即时通讯软件的自建会话（***）` 命中 OCR 出的 `文亻牛传输助手`。

**这一轮修掉的 6 个真实 bug**（都会导致"静默点空"）：
前台抢不到、OCR 读到别的窗口像素、区域裁剪坐标错、函数被定义两次、
`key:"enter"` 让 pynput 崩、点聊天行是"切换"语义。

## 03:00-04:00 · 三层策略：把高风险能力关进盒子

用户定规矩：**逆向必须藏在第一、二层之后**，因为风险太高。于是写下：

进入第三层的五个条件：① 先举证（前两层各试了什么、为何失败）② 先说明影响面/回滚/最坏后果
③ 先备份 ④ 用户**逐次**明确授权（"上次说过"不算）⑤ 只读优先。

五条红线：不碰凭据、不篡改安全软件、不改系统服务/驱动、不外发数据、不绕 DRM。

## 06:00-06:30 · P2：生命周期三件套 + 区域记忆 + OCR 小字

- `appkit.launch / wait_window / exit_app`（关窗 ≠ 退出，托盘进程要显式结束）；
- `anchor_mem.learn_region / learn_item`（区域与列表项记忆，自动外推行高）；

## 06:30-07:00 · 急停：用户要"连按两下 ESC 你就松手"

- `panic.PanicSwitch`：全局键盘监听，1.5 s 内两次 ESC 触发，**粘住不复位**；
- `panic_watch.py`：进程外看守，触发即杀掉所有自动化进程（脚本卡死也杀得掉）；
- 在 恐怖生存游戏（***） 那一局**真机触发过一次**，脚本当场硬停并交还控制权。

## 06:00-07:00 · 视觉状态判据（本项目最通用的一组）

恐怖生存游戏（***） 暴露的通用需求：看不见控件时怎么可靠判断状态。四个判据 + 一条统计：

1. **模板自学**：`capture_template` → `match_template`（返回屏幕绝对坐标）
2. **基线差异**：`set_baseline` → `diff_baseline`（0~255 平均绝对差）
3. **稳定采样**：`sample_stable`（连采两次一致才算数）
4. **悬停探针**：`hover_probe`（悬停 → 等 → 比较 → 移开）
5. **运行统计**：`vision_list`（calls / failures / retries / failure_rate 当体检指标）

**四条铁律**（全部被打出来）：
1. 模板必须**自标定**：搬别人的图，阈值 0.62 在我这里 0 命中，白守一整夜；
2. 判据要和**视角/滚动无关**：用"右按钮亮度"判断是否在监控页，视角一转就误判；
3. 状态**每轮从画面读**，变量只当缓存（"我记得灯开着"必然失步）；
4. **动画期间不要判状态**（否则反复横跳）。

## 07:00-07:20 · 恐怖生存游戏（***） 该游戏的自定义难度模式：一次通关、一次翻车

**学到的游戏机制**（都来自实际读攻略 + 实测）：
- 监控不是点出来的，是**鼠标移到底部 box 悬停**触发；点击只开不关；
- 视角能**左右平移**（鼠标贴边），左右门/灯按钮只在对应侧可见；
- Foxy 三阶段：幕布关 → 探头（眼睛可见）→ 冲刺；眼睛消失 = 已经冲了。

**成绩**：AI 全 0 通关；AI 全 5 撑到 252/545 秒被杀。

**为什么被杀**：搬了别人的模板图，`Bonnie/Chica` 检测**一次都没命中** —— 等于闭眼守夜。

**复盘结论**：全 0 通关证明"流程和眼睛"对了；全 5 失败证明"判断"没建立起来。
下次必须从**采集局（把怪物调到 20 专门拍素材）+ 分级验证**开始，而不是先写一个漂亮的循环。

## 07:20-07:40 · 游戏平台的创意工坊（***）：把"订阅按钮在哪"彻底搞清楚

- item 详情页**永远没有**订阅按钮（旧客户端、新网页布局都没有）；
- 订阅 + 在**列表页卡片的右下角**，位置规律 `(标题x + 255, 创作者y + 4)`；
- 卡片太靠页面底部时 + 会被窗口边缘切掉，先向下滚 2 格；
- 验证只认 `创意工坊日志（***）` 的 `Subscribed to item` + `content/<appid>/<id>/` 目录。

## 07:40-08:00 · GUI 授权闸门（v0.1 的收尾功能）

用户要求：把"能不能动我的鼠标"做成界面开关 —— **无色 = 没权限，绿色 = 可以**。

- 插件 `@local/dsh-mouse-permission`，注册在 `conversation.input.right`（"完全权限"右边）；
- 灰色 "鼠标·未授权" / 绿色 "鼠标·已授权"，状态存 localStorage，悬停有说明；
- 只读检查器 `mouse_permission.py`：退出码 0 / 2 / 3；
- 规则进 AGENTS.md：**agent 不得写 DOM / 改 localStorage / 用鼠标点它来自我授权**。
