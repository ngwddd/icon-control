# Icon Control v1.4.3-rc3

RC2 复审的收口版。工具数不变（96）。一条必修（错误的 `verified_absent`）+ 三条建议。

## 必修：不存在，必须是被证明的

`ui_find` 有访问预算之后，`found=0` 的含义变了：它只说明"读过的这些控件里没有"。
`execute_verified` 却仍按老语义判定，可能把还在界面上的目标报成 `verified_absent`。

现在三态判定：

| 扫描 | 结论 |
|---|---|
| 有命中 | 存在 |
| 无命中 + `scan_complete=true`（跑完且无读取错误） | **不存在** |
| 无命中 + 被截断 / 有读取错误 / 结果异常 | **未知** → `executed_unverified` |

## 三条建议（都做了）

| 项 | 修法 | 影响 |
|---|---|---|
| 宽父节点提前枚举兄弟 | `_walk` 改为逐个 `GetFirstChildControl` / `GetNextSiblingControl` | 900 项列表读 50 个就停，不再先建 900 个对象 |
| 副屏被误判越界 | `_screen_rect` 用虚拟桌面边界 | 主屏左侧的副屏（负坐标）可正常搜索 |
| `with_ids=false` 的引用缺身份 | 节点标 `identity:false`，快照降级为观察级 | 这类引用不会通过结构性身份校验 |

## 验证

- 回归 **928 项 / 0 失败 / 0 错误 / 3 跳过**（rc2：916）
- 新增 12 项：存在性三态、懒枚举、虚拟桌面边界、引用身份降级

## 已知限制

- `visited` 现在接近真实读取量，但它仍是"节点数"，不是 COM 调用数
- 模板"屏幕抓图 vs 窗口位图"两个通道的差异仍未统一，跨通道会匹配失败
- 微信 / 游戏长跑验收仍未做；当前证据是资源管理器 + Electron 自绘窗口
