# Icon Control v1.4.0-rc2

发布候选第 2 版。修 RC1 审计发现的问题，**授权模型不变**：连接即授权 + 急停 + 人机接管 + 目标窗口校验。

## 修了什么

| 级别 | 问题 | 修法 |
|---|---|---|
| P0 | 急停后删除/损坏 `local-policy.json` 会重新放行 | 急停闩存在时不再凭空生成授权时间；记录缺失/损坏按未授权处理 |
| P0 | 安装/升级/回滚会自动 `resume()` | 改为 `ensure_initialised()`：仅全新安装（无记录且无急停）时创建记录 |
| P0 | `policy disable` 只写记录、不生效 | `mode()` 现在读「环境变量 → 记录 → 默认」三级 |
| P1 | 多 HTTP 客户端复用缓存的会话身份 | 只缓存文件事实，授权负载按调用方重建 |
| P1 | `_save()` 写失败仍返回成功 | 写后回读校验，失败抛 `OSError`；进程内加锁 |
| P2 | `exit_app(force=True)` 与 `applications=['*']` 不兼容 | 通配也放行 |

另外：`resume()` 现在直接删除急停闩，不再依赖两个时间戳的先后（同一时钟刻度会判错）。

## 没有采纳的

没有重新引入控制权代际之类的额外授权机制——只修 bug，不改模型。

## 验证

- **762 项 / 0 失败 / 0 错误 / 3 跳过**（新增 14 项针对审计项的回归）
- 协议检查：stdio + HTTP 均为 90 工具、版本 1.4.0rc2、无凭证 401
- 急停链路：删记录 / 改坏记录 / 装升级 / 回滚，四种情况都保持停止
