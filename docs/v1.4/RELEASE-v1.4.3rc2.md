# Icon Control v1.4.3-rc2

RC1 的审计修复版。工具数不变（96）。五条全部是"本轮改动引入或暴露的缺陷"。

## 修了什么

| 编号 | 问题 | 修法 | 验证 |
|---|---|---|---|
| P1-1 | `ui_find` 未命中时 `max_nodes` 失效（会走完整棵树） | 访问预算与命中数分开计，返回 `visited` / `truncated_reason` | 900 子控件、预算 50 → 实际访问 50 |
| P1-2 | `index ≥ 10` 返回 `target=None` | 有效命中上限至少 `index+1` | 15 个同名按钮，`index=0/9/10/12/14` 全部可取 |
| P1-3 | 命中的元素引用缺 `AutomationId`，身份校验失效 | 只对收集到的命中读 id，批量遍历仍可跳过 | 命中带 id；200 节点查询读取 ≤5 次 |
| P1-4 | `search_region` 越界时坐标偏移/虚假命中 | 所有搜索框裁剪到可见区域，不相交即报错 | 部分越界坐标正确、完全越界报错 |
| P2 | `search_region` 与 `previous` 优先级与文档相反 | 代码改为 `search_region` 优先 | 专项测试 |
| P2 | `found=false` 仍返回 `x/y/center` | 坐标移入 `candidate` 诊断字段 | 拒绝时无坐标 |

## 代价（如实写）

P1-3 让每次 `ui_find` 最多多读 `max_hits`（默认 10）个 `AutomationId`——
每次跨进程调用约 0.04 ms（279 节点 12.7 ms 折算），一次查询约 +0.4 ms。
换回的是元素引用可区分"重建后的同名控件"。

## 基准

`task_bench.py` 现在有 6 个任务：

| 任务 | 结果 |
|---|---|
| 资源管理器整树 | 264 节点 |
| 找地址栏 | 2 个候选 |
| 记事本文档区 | 67 节点 |
| 记事本菜单 | 3 个候选 |
| **移动窗口后跟踪** | `moved_by=[60,40]`，与真实位移一致 |
| **自绘窗口定位（OCR）** | 3 个候选，**1 次 OCR 调用** |

微信没运行，所以"自绘窗口"用的是 Electron 窗口（同样没有 UIA 树）；证据里写明了用的是哪个窗口。
真正的微信/游戏长跑验收仍未做。

## 验证

- 回归 **916 项 / 0 失败 / 0 错误 / 3 跳过**
- 真机（安装后的 wheel，Windows 11）：
  - 未命中查询 `max_nodes=40` → **visited=40**、`truncated_reason=max_nodes`；默认预算下 visited=264
  - 部分越界搜索框 → `search_rect` 被裁剪到窗口内（`[80,120,380,140]`）
  - 完全在窗口外 → 报错"与窗口没有交集"
  - 分数不足 → `found=false`，**无 x/center**，最佳像素位置在 `candidate`，`reason=below_threshold`
  - 命中带 AutomationId（`[["地址栏","TextBox"], ...]`）

### 一个没修的现象（如实记录）

用屏幕抓图存模板、再用 `hwnd` 走窗口位图匹配时，两者可能不一致（本例中同一位置匹配不上）。
这属于"两个抓图通道的缩放/来源差异"，不是 rc2 改动的范围，没有在这版处理；
需要的话下一轮单独立项。

## 已知限制

- 视觉跟踪仍是"局部重搜"，不是长期身份跟踪：缩放、旋转、大面积重绘时会给
  `below_threshold` / `ambiguous`，这是有意为之。
- `truncated=true` 时 `found` 是下界；要总数请调大 `max_nodes` / `max_hits`。
