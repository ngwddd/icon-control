# Icon Control v1.4.2-rc2

RC1 的审计修复版。**不新增工具**（仍是 96 个），修的是"点了会点到谁"和"失败后按键收不收拾干净"。

## 修了什么

| 编号 | 问题 | 修法 |
|---|---|---|
| E01 | 窗口截图被遮挡时，点击会落到遮挡它的窗口上 | 窗口 frame 记住 `target_hwnd`，点击前核对着落窗口；不匹配抛 `target_occluded`，不发送输入 |
| E02 | 多区域截图只有第一张有 `frame_id` | 每个区域各自带 `frame_id` / `source_rect` / `image_size` / `index` |
| E03 | `batch` 的 `key` 步骤基础键未纳入清理 | 基础键也追踪；收尾重试释放，仍失败进 `release_failed` 并整批判失败 |
| E04 | `hold_ms` 用普通 sleep，不可中断 | 改用协作式 sleep（急停/接管可打断），上限 10 秒并标注 `capped` |
| E05 | 图片右下边界映射到画面外一像素 | `to_physical()` 改为半开区间 `0..width-1`，越界直接拒绝 |
| E06 | 长按不支持组合键 | `key_press("ctrl+w", hold_ms=...)` 可用，返回 `chord: true` |

## 为什么先修这两条

E01 和 E03 决定的不是"功能多不多"，而是**会不会点错窗口**、**失败后键盘会不会卡住**。
这两件事出问题的代价，比多几个工具大得多。

## 验证

- 回归 **880 项 / 0 失败 / 0 错误 / 3 跳过**
- 新增 10 项：遮挡拒绝点击、可见放行、屏幕截图不检查、多区域 frame 对应、
  基础键释放失败重试、边界半开、长按截断、长按组合键

### 真机结果（Windows 11，本版 wheel）

| 场景 | 结果 |
|---|---|
| 多区域截图 | ✅ 两块各自 `frame_id`（`f_9c1d069e` / `f_80faac35`），第二块 `source_rect=[300,200,160,90]`、图片 (10,10) → 屏幕 (320,220) |
| 遮挡后点击 | ✅ 截图记事本 → 用另一个窗口盖住 → 落点顶层窗口不是目标 → **`target_occluded` 拒绝**，鼠标坐标前后完全没动 |
| 长按 | ✅ `hold_ms=180` 释放正常，`capped=false` |

遮挡这一条是直接调用动作层验证的（绕过权限闸门），证明拒绝发生在**注入之前**。
