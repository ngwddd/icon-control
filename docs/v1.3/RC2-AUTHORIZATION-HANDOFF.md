# v1.3.7 RC2 修改交接

基线 5d268bdfdd1cb7c935998b5a137d429fb876efe1，分支 codex/v1.3.7-rc2，版本 1.3.7rc2。

## 本轮代码修改

- IC-137-01：迁移身份测试的签名会话注册、请求缓存字典及跨会话拒绝断言。只更新 click 和 control_status 的既定 API 快照。CI 显式使用 UTF-8，保留完整测试与 SDK 步骤。
- IC-137-02：执行点拒绝未获授权的应用时，按实际目标 HWND/PID 生成当前会话的补授权请求。重复请求缓存按真实应用身份分开。
- IC-137-03：paste 的动作权限包括 clipboard_read，保存旧剪贴板前和读取 helper 内都检查读取权限；提供文本时仍独立要求 clipboard_write。
- IC-137-04：终态和过期记录即时回收；重复活跃请求复用同一 ID 且保留原到期时间；每 Agent 最多 16 个活跃请求，整体上限 128。
- IC-137-05：新原生宿主和 Tk 高级入口均使用授权操作 ID。发送 grant 后通过 grant_status 回读确认，出错则提交 cancel_grant。取消记录阻止同 ID 的迟到授权；取消旧操作不会撤销其他新操作。
- IC-137-06：补充 tests/test_v137_requests.py 中的身份冒充、请求重放、进程替换、会话隔离、队列回收、超时取消与心跳代际等测试定义。
- IC-137-07：工作区摘要固定在首次签名会话注册中。再次注册和进程 chdir 使用原摘要，同目录的不同传输会话仍隔离。
- IC-137-08：原生宿主通过状态锁串行处理授权、续期、撤销与心跳 IPC。心跳结果经窗口消息交给 UI 线程，旧代际结果丢弃。

## 升级要点

使用 RC2 构建的 wheel 运行 tools/install.ps1；同时重启授权桥、原生宿主与 MCP 客户端后，为实际请求会话重新授权。手动打开原生窗口与带 request_id 的自动请求继续使用各自的明确选择流程。

请使用原审计中的场景检测，尤其是 A 已授权后 B 请求、同一会话跨应用补授权、128 个请求填满后终态回收、grant/revoke 超时与 50 次窗口开关。保留对应源码 SHA 的真实证据。
