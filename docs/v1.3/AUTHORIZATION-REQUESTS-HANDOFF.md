# v1.3.7rc1 授权请求身份整改交接

基线为 2987cb0bb1691679d01c8434906609a62d854e0a。代码位于 codex/v1.3.7-authorization。按本次用户要求只修改代码，测试、真机验收和发布签收由用户负责。

## 修改后的使用流程

1. 从真正执行任务的 MCP 发起操作。拒绝响应包含 request_id、所需范围及实际调用者诊断。
2. 原生授权窗口显示该请求的 Agent、PID、工作区摘要、目标应用和权限。窗口中的“本次所需”精确包含请求所需能力。
3. 原授权属于其他会话时明确提示，确认后原子替换。当前会话缺权限或缺目标应用时直接进入补授权。
4. 请求超过 120 秒、调用者退出或目标进程身份改变时失效。重新发起操作生成新请求。取消或已消费请求不能再次批准。
5. 没有待授权请求时，热键入口提供活跃会话和目标应用的明确选择。多个 Agent 不会自动选最新的一个。

多个请求保存在桥的独立签名队列中，按进入顺序处理。相同调用方的重复请求会在短时间内复用请求号。桥重启后旧请求失效，需要重新发起。请求的批准与授权代际替换在同一个桥锁中串行执行。

## 身份隔离

旧版基于 cwd 的租约继承已移除。授权绑定实际传输分配的 agent_session，工作区摘要保留用于识别。相同 cwd 下的不同 stdio 进程、不同 HTTP 凭据使用不同会话。共享同一 HTTP 凭据的连接表示同一客户端主体；需要相互隔离的客户端应配置不同凭据。

升级时请同时重启 MCP 服务、授权桥和原生授权宿主，再为实际请求方批准。旧安装和新源码应使用独立版本目录，避免运行中混用模块。

## 实际调用者诊断

在真实 MCP 通道调用 control_status，可选传入 hwnd 和 requested_scopes。返回的 authorization_diagnostic 包括实际会话、工作区摘要、连接 PID、当前批准对象摘要、权限差集、目标应用、bridge_granted、caller_granted 和 reason。

诊断不包含 Token、密钥或输入文本。bridge_granted 不能单独证明 caller_granted。

acceptance_run.py 新增 --caller-diagnostic，接收上述调用者导出的诊断对象。该文件仅用于预检参考，要求 30 秒内的新记录。实际执行进程仍必须通过自己的权限闸门。原先创建“预检 Python 会话”再宣称 DSH 已授权的逻辑已移除。

## click 兼容行为

- click(button="left") 点击当前光标位置。
- click(button="left", x=100, y=200) 使用物理屏幕坐标定位后点击。
- x/y 必须同时提供，必须是有限数值。非法额外参数由工具 schema 拒绝。
- 定点点击在实际按下前核对光标位置和目标进程 PID、启动时间、可执行文件身份，并检查人类批准范围。
- 保留 mouse_move 加 click 的原用法，以及原有 89 个工具和别名定义。

## 代码范围

- agent_session.py：工作区摘要与传输会话绑定的身份。
- consent_requests.py：独立请求对象、签名、TTL 和状态流转。
- consent_ipc.py：实际管道 peer 校验、请求队列、原子授权和调用者诊断。
- permission.py / permission_bridge.py / capabilities.py：移除跨会话租约继承，请求方退出后授权失效。
- native_consent.py / native_dialog.py：请求优先、补授权、明确选择、本次所需预设、无授权按钮的错误通知、撤销未知状态。
- actions/mouse.py / input_guard.py / __init__.py / 工具定义与分发：兼容可选坐标与最终注入点核对。
- tools/acceptance_run.py：实际调用者诊断预检。

本交付未运行单元测试、构建检测、原生窗口操作或微信操作，没有生成通过报告或正式发布标签。
