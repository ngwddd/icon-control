# Icon Control v1.3.8

项目所有者已明确批准合并 PR #8 并发布正式版。

## 更新内容

- 提供运行进程版本、工具定义指纹及 click 实际 schema 诊断，构建包记录源码来源，方便识别旧 MCP 工具缓存。
- 没有可信目标时要求人工明确选择应用；同一工作区不同会话仍独立授权。
- 输入结果增加文字长度、直引号计数、哈希及草稿核对指引，保留 executed_unverified 语义。
- 新增独立 scroll，支持可选坐标、限定滚轮步数及注入前目标复核。原有 89 个工具保留，共 90 个。
- guarded_click 要求正向页面身份证据，拒绝零/非法阈值与无 OCR 证据；绑定顶层 HWND，防止同进程其他窗口遮挡后误点。
- 微信朋友圈宏要求明确目标窗口和非空页面参数，失败停止且不自动重试点击。
- 安装及 stdio/HTTP 协议检查共用包内工具清单，移除固定工具数判断。
- 修正技能和文档中的启动、授权继承及收尾规则：保留用户原有或明确要求保留的应用窗口。

## 升级

安装新 wheel 后重启实际 MCP 连接、授权桥及原生授权宿主，重新批准实际请求会话，并在客户端刷新 tools/list。客户端若仍未展示 click 的 x/y 或 scroll，请检查 control_status.runtime_contract。

运行摘要或 Unicode 注入成功不能证明微信草稿逐字一致，发送前仍需核对内容。微信宏中的历史坐标只作候选，页面条件不满足时停止。
