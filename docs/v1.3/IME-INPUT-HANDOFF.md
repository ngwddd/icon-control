# PR5 真机反馈输入层修复交接

本轮依据用户测试报告，修复基线为 36b8d76。报告中原生授权和 T2 已通过，T1/T3 在中文输入法环境失败。

## 源码改动

- 前台文字输入统一使用 KEYEVENTF_UNICODE，ASCII、符号、中文与非 BMP 字符均按 UTF-16 注入，避免 VkKeyScan 路径触发输入法组字。
- 每次 SendInput 核对实际返回数量，拒绝或中途失败抛出异常并清理本进程持键。
- 标准 Edit、RichEdit、Windows Forms Edit 控件使用 EM_SETSEL、WM_COPY、WM_CUT、WM_PASTE 处理 Ctrl+A/C/X/V。校验当前焦点、顶层窗口、目标应用和执行权限，焦点变化时拒绝。
- 其他控件保留虚拟键快捷键行为，需要单独确认目标应用兼容性。
- type 返回实际注入字符数，以及 status=executed_unverified、verified=false。success 表示输入事件已发送。应用文本是否逐字正确仍由应用后置条件确认。
- 对自定义输入控制器和已有定向窗口输入保持调用兼容。

## 请用户复测

1. 按原报告的安装和 desktop_smoke.py 流程重跑 T1/T2/T3，保持中文输入法开启。
2. 最小组合键场景输入 ABCDE，Ctrl+A，再输入 Z。核对内容严格等于 Z。
3. 输入 Abc123[]\\、中文第二行✓、混合大小写及 emoji，核对全角符号、遗漏和残留。
4. B11/B12/B13 增加“中文输入法开启时逐字一致”前置条件。对 Electron/浏览器编辑框另行复测 Ctrl+A/C/V。
5. 验证撤销、用户接管、双 ESC 后剩余输入停止，已持有的键释放。
