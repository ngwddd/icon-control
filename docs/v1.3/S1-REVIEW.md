# S1 安全内核复审

根因：工具可见性名单与内部执行脱节；桥缺 Token 仍放行、Origin 前缀接受伪域；
心跳覆盖动作导致撤销丢失；claim 越过用户接管；监听失败放行；静默时间窗吞掉物理输入；
旧 OCR 和环境变量可授予执行权限；双 ESC 自动重复可能误触。

修改：统一数据目录与签名状态；Token 从首请求强制验证；来源按 URL 结构检查；
用户动作与心跳分开、撤销不被心跳恢复；工具能力覆盖输入、窗口、配置和资产写入；
直调与 MCP 都走执行边界，注入逐事件检查，授权或接管代际变化取消旧任务；
使用 Windows injected 标志区分输入，监听启动失败拒绝；急停仅识别两次独立物理按键，释放本进程持有的键。

阶段验证：当时 27 个隔离安全回归通过，无 skip；12 个既有 program 逻辑测试基线通过。
候选版补查后安全专项增至 32 项；完整最新结果与限制见 VALIDATION.md。
HTTP 测试使用临时端口、测试专用 Token 和临时状态目录，不触碰玩家／宿主授权。
第二遍代码复审另外修复了 claim 竞争、临时控制器持键丢失和桥重启会话复用。

限制：此为代码及隔离回归证据。尚需真实物理鼠标接管、双 ESC、长按释放、
多窗口客户端断线／重连测试；不能把本报告当作 P0 真机验收通过。
信任边界是当前操作系统账户：同账户读取 Token、注入进程或修改代码不在签名文件的隔离能力内。
所有阶段完成及干净环境、真机验收通过之前，不发布正式 v1.3.0。

回滚：git revert 本阶段提交；旧版仅作开发对比，不重新启用无 Token 或 OCR 授权路径。
