# 授权怎么用（v1.3.7 与后续修复）

热键 Ctrl+Alt+Shift+F9（可回退 F7/F12/G）或托盘打开原生授权窗口。DSH 胶囊可打开原生入口，网页本身不能授予权限。

## 选择实际请求方和应用

- 工具因缺授权被拒时，窗口显示签名请求中的实际 Agent、目标应用和权限；已有可信目标不会改选其他应用。
- 请求没有目标时会明确提示“尚未确定要操作的应用”，必须人工选择；即使只有一个候选也不自动选中。
- 多 Agent 时明确选择实际请求者，不能回退到最新注册会话。
- 应用授权绑定 PID、进程启动时间及路径；进程重启或身份变化需要重新确认。
- 常用权限为 screen_read、input、text_entry；剪贴板读写、文件读写/删除、进程启动及关闭窗口等按实际需要独立批准。
- 同目录的新 Agent 会话也不会自动继承租约。工作区相同不能替代实际连接身份。

## 状态与撤销

仅后端确认的当前请求方授权可显示已授权；通信异常显示未知并停止正向续期。通知窗口保持打开时，后台仍会尝试否定心跳。撤销未确认不得声称已成功。

原生宿主退出、用户接管、急停或租约到期会阻断后续动作。双 ESC 急停和持键清理保持有效。不要把其他会话的全局授权当作当前 Agent 已获批准。

## 版本与工具缓存排障

读取实际 MCP 调用返回的 runtime_contract，或 control_status.runtime_contract，查看 server_version、tools_sha256、click_input_schema、source_commit。安装包缺少构建来源时 source_commit 为 null，不推断为主分支最新版本。

独立终端运行 `icon-control check` 只说明该解释器的安装情况，不能证明 DSH 正在使用同一个 MCP 进程。宿主若只看到旧 click(button) 定义，应重启实际 MCP 连接并重新发现 tools/list；服务端无法强制所有宿主丢弃缓存。

升级后重启 MCP、授权桥和原生宿主，并为实际请求方重新授权。用户原本打开或要求保留的应用不因排障或任务收尾而关闭。
