# Icon Control v1.3.6

这一版修的是"授权窗口自己不可靠"的三件事，外加把验收从看运气变成可复现。

## 修复

- **同时开出多个授权窗口**：创建单实例互斥体后，用 `kernel32.GetLastError()` 读错误码，而它是一次新的 Win32 调用，值已经被封送过程冲掉——每个宿主都以为自己是第一个。改用 `ctypes.get_last_error()`，并给 `show()` 加重入保护。实测连续两次唤起 → 1 个宿主、1 个窗口。
- **授权窗口开着时心跳会停**：心跳原本挂在 `WM_TIMER` 上，模态对话框一开就收不到消息，状态文件 15 秒内变旧，后续调用被判未授权——表现是"明明刚授权，下一项就说没授权"。心跳改到后台线程。
- **窗口显示前先向桥核对状态**：撤销后不会再显示"已授权"。
- **偶发抖动的测试**：`test_independent_review` 读进程 pid 文件时可能读到空内容（写完文件才写内容），现改为轮询重试。

## 验收工具链

- 新增 `tools/acceptance_run.py`：跑用例前先过七项前置检查（干净工作区、授权桥、唯一宿主、停止闩、有效授权、夹具还原置前、残留窗口），能修的自己修，修不了直接拒跑，并把失败分成 `harness` 与 `product` 两类。
- **证据不再进 git**：`docs/v1.3/evidence/` 与 `acceptance.json` 是运行产物。以前每提交一次证据就移动 HEAD，证据立刻相对自己产生的提交变 stale——这是"数字看起来一直在漂"的主要来源。
- 新增 `--repeat`：连跑两次并打印每题状态序列，抖动变成可数的一行。
- S5 用例修正：B22 的遮挡窗口改为只盖目标按钮（深灰、带标签），不再像"屏幕黑了一下"；B28 分支改用点击驱动，不再依赖滚轮落在哪个控件上；被人工接管打断的用例重试一次并记录尝试次数。

## 结果

- 回归：**550 项 / 0 失败 / 0 错误 / 3 跳过**。
- 真机 S5：**15 项全过**（B11 B12 B14–B22 B24 B26 B29 B30），绑定提交 `494b4e5e`，工作区干净。
- 未签收：B28（抓帧 0.25 缩放下的视觉条件探测不稳）及其余需要人工/环境条件的 16 项。

## 升级提醒

改的是桥与宿主的 IPC 与生命周期，**升级后需要重启 `permission_bridge` 和宿主**；重启会让已发出的授权失效，需要重新按一次热键。
