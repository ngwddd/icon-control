# v1.3.0rc2 补充修复与发布判断

> 历史报告：对应 3a0b8dab 的早期 RC2，不代表本轮原生授权协议或当前源码的验收结果。最新整改见 [SECURITY-REMEDIATION.md](SECURITY-REMEDIATION.md)。原始记录保留，旧心跳和 Token 方案已被替换。

日期：2026-11-03（Asia/Shanghai）。本轮延续 PR #1，不把候选版直接改标为正式版。

## 本轮修复

- SetCursorPos 的移动可能不带注入标志，导致助手自我接管。现在默认及旧原生控制器的绝对／相对移动统一走 SendInput，标记自身注入；失败抛错，禁止回落到 SetCursorPos。
- 坐标作用域采用线程级物理像素上下文并在退出时恢复，读取物理光标位置，避免不同 DPI 与宿主线程状态造成偏移。
- MCP 权限检查抛异常时，对所有工具无条件拒绝分发，覆盖 run_script、track、macro_run 和旧只读工具的故障注入。
- 长期 Token 从 URL 查询参数移到 Authorization 请求头；删除图片信标路径，增加受限 CORS 预检。
- DSH 后台会把网页计时器节流到约一分钟，超过原有 15 秒授权有效期。新增认证的只读事件流，网络事件驱动客户端确认心跳；服务器推送本身不能授权或续期，冻结／断开的客户端仍会超时拒绝。
- 热重载会替换旧定时器与旧连接，不依赖宿主重新执行 apply()。客户端会同步服务端状态，不把旧本地绿色当成授权。
- 89 个工具全部显式声明 effects，新工具漏声明时不能注册；纯读参数与写参数有独立规则，未知模式按最高声明权限检查。
- 通过现有 run_script 的 scroll 指令补齐滚轮能力，未增加 MCP 工具数量。

## 用户新增的一秒接管策略

真人鼠标持续移动满 1 秒才触发接管。停顿超过 350ms 重新开始计时，多次短挪不累加，重复坐标不算持续移动。
键盘、物理点击、滚轮、撤销授权和双 ESC 维持立即生效。助手带注入标记的移动不参与真人计时。
触发后仍会取消原任务的代际并释放本进程持有的键；claim 不得覆盖已接管状态。

9 项专项回归覆盖短挪、连续移动、停顿重置、重复坐标、持键释放、任务取消及监听入口。
完整回归：409 项运行，404 通过、5 项明确跳过，0 失败／错误。

## 对用户补交 rc1 报告的核查

报告最后声明 rc1 通过 20 项，另 4 项只在 v1.2 上通过。不能把它当作本次候选版的 32 项全绿。
已找到对应 JSON／脚本；其中 b10-result.json 仍为 ok=false，而文字报告称后续更换检查入口后通过。
因此该项存在证据版本冲突，需以新的跨进程急停复测补齐，不能直接改成通过。
其他旧证据也需标清被测版本、实测 DPI、时延范围及是否经过产品输入入口。

## 正式版结论

当前仍为 NO-GO：B04 撤销授权、100%／200% DPI、干净 Windows 账号安装，以及独立 P0 复审与证据签收尚未全部完成。
干净 CI 主机的构建与 SDK 互通不自动等同于已登录的干净 Windows 11 桌面账号验收。
acceptance.json 保留缺项，release_gate.py 仍应阻止正式发布；不会为了发版跳过这些条件。

候选安装已使用独立版本目录，桥端口统一配置为 18766，与原 18765 区分。已有常驻工作进程需重启才能加载新的移动策略。
